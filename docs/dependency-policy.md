# 依存更新と48時間の待機期間

JavaScriptはpnpm 12、ビルド用Node.jsは`.nvmrc`の26.12.1を使います。`packageManager`でpnpmを固定し、`pnpm-lock.yaml`と5つの`Cargo.lock`をコミットします。Node.jsはビルド時だけ必要で、配布アプリのmacOS 27以降という条件は変わりません。

## JavaScript

`pnpm-workspace.yaml`の`minimumReleaseAge: 2880`で、直接・間接依存に公開後48時間の待機期間を設定します。`minimumReleaseAgeStrict: true`と`minimumReleaseAgeIgnoreMissingTime: false`により、新しい版しか選べない場合や公開日時を取得できない場合は導入を失敗させます。現在、JavaScript依存の例外はありません。依存のビルドスクリプトも未承認では実行させません。

```sh
pnpm install --frozen-lockfile
pnpm run check:dependencies
pnpm run build
```

新しい依存へ更新するときは`pnpm update --latest`を使えます。メジャー更新も対象ですが、48時間の制約は維持します。ロック済み依存もpnpmのポリシー検証を受けます。pnpm本体と、そのネイティブ版を起動するプラットフォーム別パッケージは、実行前にPythonの検査でも公開日時を確認します。

## Rust

安定版Cargoにはpnpm相当の公開後待機設定がないため、`scripts/check-dependency-age.py`でcrates.io sparse indexの公開日時とチェックサムを検査します。アプリ・音声認識・補正・モデル準備・比較計画の5つのロックファイルについて、実行プラットフォームで使われないものも含め、全レジストリ依存を検査します。承認したセキュリティ修正版を除き、公開後48時間未満であれば停止します。公開日時不明・チェックサム不一致・未対応の外部レジストリ／Git依存は、セキュリティ例外でも許可しません。リポジトリ内のpath依存には公開日時がないため、この公開待機検査の対象にしません。

通常CIはこの検査が成功してからCargoのコンパイルを開始します。Releaseとモデル評価のワークフロー、通常のアプリ用ランタイム準備にも同じ検査を組み込みます。公開メタデータのキャッシュは不変の公開日時を再利用し、ロックファイルに新しい版があれば取得し直します。依存のコードやbuild.rsは、公開日時の検査では実行しません。

手動の`cargo update`自体には待機期間の制約はありません。更新後、**コンパイルより先に**次を実行してください。

```sh
python3 scripts/check-dependency-age.py
```

検査で新しすぎる版が見つかったら、48時間が経過するまで取り込みを待つか、対象のロックファイルに対して`cargo update --manifest-path <Cargo.toml> -p <crate>@<version> --precise <適格版>`で直近の互換版に固定します。再検査が成功してから、`--locked`でビルド・Clippy・テストを実行してください。メジャー更新は依存指定と利用APIも合わせて変更します。

Renovateを実行する場合も、`renovate.json`の`minimumReleaseAge: "2 days"`と`timestamp-required`を適用します。この設定ファイルの追加だけではRenovateサービスは有効になりません。Renovateが更新する場合でも、間接依存を含む最終結果はCIで検査します。

## セキュリティ修正は待機期間より優先

上流の修正内容・アドバイザリで確認できたセキュリティ修正版は、48時間を待たずに取り込みます。パッケージ名全体を除外せず、`dependency-security-exceptions.json`にエコシステム・正確な版・レジストリのチェックサム・理由・一次情報URL・有効期限を記録します。例外は公開後最大7日以内に期限を迎える必要があり、別の版や改変されたパッケージには適用しません。48時間経過後は通常の検査で通り、例外は適用されなくなります。CIの公開日時レポートには、実際に適用した例外と根拠も残します。

npmの例外を追加する場合は、同じJSONに`ecosystem: "npm"`、`checksum`にレジストリの`sha512-...` integrityを記録し、pnpmの`minimumReleaseAgeExclude`にも`["package-name@1.2.3"]`のように完全一致の版だけを指定します。ここはインラインJSON配列（有効なYAML）にしてください。CIは第三者のYAMLパーサーを起動する前に、このリストと例外記録が一致し、通常の48時間・日時必須・厳格モードが維持されていることを検証します。ワイルドカードやパッケージ名だけの指定は許可しません。

Renovateの脆弱性修正PR提案には待機期間を課しません。ただし、この設定だけでCIの制約を無条件に解除することはなく、修正の確認と上記の版限定の例外記録が必要です。

今回確認したセキュリティ修正・関連調査は[依存のセキュリティ確認](security-dependency-review.md)に記載します。

## 今回の更新

公開後48時間を経過した安定版を調査し、TypeScript 6→7、pnpm 12、Node.js 26、rubato 0.16→5、sha2 0.10→0.11へ更新しました。Tauri・Whisper・llama.cppバインディングなどは公開済みの最新安定版を維持し、その他の直接依存の下限も調査時点の適格版へ更新しています。間接依存は親パッケージが要求する互換範囲内の最新版を選びます。

brotli-decompressor 6.2.0の入力エラー処理の修正と、それを要求するbrotli 9.1.0は、確認できたセキュリティ改善として48時間未満でも採用しました。通常の性能改善・テスト変更だったerased-serde 0.4.11とsmallvec 1.16.4は、待機条件を満たす互換版を維持します。GitHub Actionsも公開後2日以上経過した現行リリースへ更新し、可変のメジャータグではなくコミットSHAで固定しています。

`v0.0.1`も初回Releaseに使えます。タグに合わせてアプリのバージョンをCIが設定します。既に`0.1.0`などのアプリを使用している場合、自動更新では`0.0.1`へ下げません。初回のDMGから手動でインストールしてください。
