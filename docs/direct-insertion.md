# 他アプリへの直接入力

## 有効化と使い方

初期状態は無効。以前の設定ファイルに項目がない場合も無効として読み込む。
利用する場合は設定画面の「認識結果を録音開始時の入力欄へ直接入力する」を選び、
「設定を保存」を押す。設定ファイルへ保存する追加項目は `autoInsert` の真偽値だけ。
音声・認識結果・入力欄の内容は保存しない。

「アクセシビリティの許可を確認・設定」を押し、macOSの
「システム設定 → プライバシーとセキュリティ → アクセシビリティ」で
実際に使用するVoice Inputを許可する。設定後、必要ならアプリを明示的に終了して再起動する。
この許可操作は明示的なボタン操作時だけ行い、起動時や録音時に自動で要求しない。
マイクの許可は従来どおり録音開始時に確認する。

1. ローカルモデルを読み込む。
2. 入力先アプリの編集欄にカーソルを置く。置換する場合は対象の文字列を選択する。
3. 録音ショートカットで開始し、話し終わったら同じショートカットで停止する。
4. 認識完了時も同じ入力先・位置・内容なら、認識結果をその選択範囲へ挿入する。
   選択が空ならカーソル位置へ追加する。前面アプリ・クリップボードは切り替えない。

Voice Inputの画面で録音を開始した場合は、別アプリの入力先を取得できないため自動入力を見送る。
許可なし・入力先変更・非対応の欄でも録音と認識は継続し、結果を画面に保持する。
メニューバーの「設定・認識結果を表示」から理由と結果を確認して、必要なら手動でコピーする。

一度の録音で自動入力を試みるのは最初の認識完了時だけ。
「文字起こし・再試行」で同じ結果を二重挿入することはない。
設定を無効にして保存すると、待機中の入力先も無効化する。
再度有効にした場合は次の録音から入力先を記録する。

## 入力先の確認と対応範囲

録音開始時に、前面アプリのフォーカス要素・PID・選択範囲と、入力内容の変更検出用ハッシュを記録する。
認識完了時に同じ要素・アプリ・選択範囲・内容であることを再確認する。
途中で入力先アプリや入力欄、カーソル／選択範囲、内容が変わった場合は挿入しない。

Accessibilityが編集可能な `AXSelectedText` を公開するテキスト欄に対応する。
入力は `AXSelectedText` への1回の書き込みだけで、欄全体の置換、キー入力の合成、
クリップボード経由の貼り付けへのフォールバックは行わない。
TextEditでの日本語・絵文字を含むカーソル位置と選択範囲の置換をCIで検証する。
アプリ独自のエディターやWebの入力欄はAccessibilityの実装次第で非対応になる。

パスワード用の役割・サブロールを持つ欄、役割や安全性を確認できない欄、読み取り専用欄、
テキスト以外の要素、非常に大きい欄（100万UTF-16コード単位超）は対象外とする。
保護された欄は役割を調べた時点で拒否し、値や選択内容を取得しない。
アプリが通常のテキスト欄として公開する独自の入力欄については、そのAccessibility情報に基づいて判断する。

入力先APIの確認と書き込みは別の操作であり、OS全体のフォーカス操作と原子的には実行できない。
書き込み直前にもフォーカスを再確認するが、開始済みの書き込みを「破棄」で取り消すことはできない。
失敗したAPI呼び出しも自動で再試行せず、結果を残して利用者が入力先を確認できるようにする。

## 取得する情報と保持期間

自動入力を有効にした場合だけ、録音開始時の入力先を調べる。
内容変更の検出には対象入力欄の値を一時的に取得してハッシュ化し、元の文字列は保持しない。
ハッシュは変更検出用であり、暗号化・匿名化を目的とするものではない。
ハッシュ・要素の参照・位置は専用スレッドのメモリ内に限定し、UIへ渡したりファイルへ保存したりしない。
認識完了、破棄、新しい録音、無効化、終了で入力先の参照を解放・無効化する。

この読み取りは誤入力防止のためで、認識モデルへ入力欄の文を渡さない。
画面コンテキストによる認識補正・OCRの設定とは別の機能であり、これらは引き続き未実装。
音声・文字起こし・対象欄の情報を外部へ送信しない。
クリップボードへの書き込みは既存の「結果をコピー」を明示的に押した場合だけ。

## CI

製品アプリを通常起動し、実際のマイク・ローカルASR・Accessibility APIを経由して検証する。
製品側にはCI用の権限・音声・認識結果の注入や、入力先の差し替えは設けない。

- 製品アプリのアクセシビリティ許可をリセットし、未許可の状態では入力先を変更せず、結果と理由を表示する。
- 明示的な許可ボタンからシステム設定を開き、製品アプリのスイッチを操作する。
  使い捨てのCIランナー内だけで一時管理者アカウント・ランダムな資格情報を作成し、実際のOS認証ダイアログを操作する。
  資格情報はログ・Artifactに含めず、アカウントとともに終了時に削除する。製品や個人利用の手順へは含めない。
- アプリを再起動し、製品自身が `AXIsProcessTrusted` で許可済みを確認できる状態で検証する。
- TextEditでカーソル位置への挿入・選択範囲の置換を認識結果全文と比較する。クリップボードが変わらないことも確認する。
- 合成のネイティブ入力欄で、別の入力欄・位置・内容・アプリへの変更、パスワード欄・読み取り専用・非テキスト要素、認識中の破棄を検証する。

画像・判定は `macos-window-smoke-1` Artifact（末尾は試行回数）の
`insertion-denied/`・`insertion-grant/`・`insertion/` に保存する。
実際の個人Macでの初回許可はそのMacの利用者が行う。[個人利用ガイド](user-guide.md) を参照。
Developer ID証明書・公証は引き続き先送りする。
