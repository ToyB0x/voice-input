# ローカルOCRと最終補正（実験的）

Whisperの文字起こし後に、軽量なローカルQwen3モデルで校正・句読点・改行を整えるプレビューです。元の認識結果を保持し、補正結果は自動入力せず、確認後に明示的にコピーします。音声・画像・取得テキスト・補正結果をクラウドや外部APIへ送信しません。

## 準備と使い方

Macで従来の開発環境を用意し、`npm ci` → `npm run tauri dev` を実行します。npmのTauriコマンドは、先にRust製の補正ランタイムをビルドしてアプリのリソースに配置します。llama.cppとWhisperのGGMLは別プロセスで動くため、異なるネイティブライブラリのシンボルが衝突しません。モデルの自動ダウンロードやHTTPサーバーの起動は行いません。

アプリ内の[モデル準備・プリセット](model-setup.md)から準備でき、従来の手入力パスも使えます。モデルの準備は利用者が明示的に行います。公式Qwen GGUFの固定リビジョン・サイズ・SHA-256を検証してから配置します。

```bash
python3 scripts/prepare-correction-model.py --model qwen3-1.7b "$HOME/Models/Qwen3-1.7B-Q8_0.gguf"
# 大きい候補を比較する場合
python3 scripts/prepare-correction-model.py --model qwen3-4b "$HOME/Models/Qwen3-4B-Q4_K_M.gguf"
```

候補は公式のQwen3 1.7B Q8_0（約1.83 GB）と4B Q4_K_M（約2.50 GB）です。いずれもApache-2.0で、重みはアプリに同梱しません。取得元・ハッシュは `scripts/correction_models.py`、エンジンのバージョンは独立したCargo.lockに固定しています。モデルサイズと量子化方式の両方が異なるため、比較はパラメーター数だけの効果を測るものではありません。

1. 「補正モデルの絶対パス」とCPU / Metalを設定して「設定を保存」します。
2. 必要な取得元と利用先を選び、設定を保存してから、別アプリの入力欄で録音を始めます。
3. 文字起こし後に「最終補正をプレビュー」を押します。
4. 元の認識結果と補正結果を比べ、内容を確認してから「補正結果をコピー」を押します。

補正を使わない場合、モデルパスを空欄のままにします。起動時に補正モデルを読み込まず、明示的なプレビュー操作時だけ別プロセスを起動します。各プレビューでモデルを読み込むため、常駐モデルより起動コストがあります。初回のGPU初期化はさらに時間がかかる場合があります。途中でも破棄で中止でき、アプリは約150秒で補正を中止して原文を残します。Metalの必要なSIMD演算機能がないGPUでは、モデルを読み込む前に明示的なエラーにし、利用者がCPUを選べます。GPUへ重みを配置できるだけでは十分ではありません。CIのApple Paravirtual device（Apple5相当）はこの機能を公開していないため、CPUで比較と結合テストを行い、Metalは利用不可を正しく検出することを検証します。実際のGPU推論を確認できていない場合、GPUで成功したものとして扱いません。

証明書・公証は個人利用中は引き続き先送りします。インストール、隔離属性、アドホック署名、更新時の権限再設定は[利用ガイド](user-guide.md)を参照してください。

## 取得元と利用先

| 設定 | 初期値 | 動作 |
|---|---|---|
| Accessibilityで入力欄を取得 | 無効 | カーソル周辺の範囲だけを読み取る |
| 入力欄を撮影してOCR | 無効 | 入力欄の矩形だけをScreenCaptureKitで取得し、Apple Visionで日本語・英語OCR |
| Whisperへ取得テキストを渡す | 有効 | 取得元が有効な場合だけ、Whisperのinitial_promptへ渡す |
| 最終補正へ取得テキストを渡す | 無効 | 取得元が有効な場合だけ、初回の補正プレビューへ渡す |

取得元が両方無効、または利用先が両方無効なら取得しません。旧設定の`recognitionContext`はAccessibility取得の設定として引き継ぎ、従来どおりWhisperへ渡します。新しいOCR・最終補正への利用は移行時にも無効です。

録音ごとに一つの文脈を固定し、Whisperと最終補正で共有します。両取得元がある場合は各350 UTF-8バイト以内をラベル付きでまとめ、片方だけなら最大768バイトに制限します。モデル同士に異なる時点の画面情報を渡さず、前の録音へ遡ったり次の録音へ引き継いだりしません。

Whisperの再試行では文脈を再取得・再利用しません。最終補正へ渡す設定の場合は、同じ録音の初回補正までネイティブメモリに文脈を保持します。補正の再実行は文脈なしです。新しい録音・破棄・取得／利用設定の変更・アプリ終了で解放します。認識の失敗や無音で補正対象がない場合も解放します。モデルが未設定で補正をまだ行っていない場合は、補正または録音の破棄まで保持します。

## OCRの範囲と権限

OCRにもAccessibilityの許可が必要です。保護された欄・読み取り専用・非テキスト要素・Voice Input自身を撮影しないことを確認するために使います。さらに、明示的な「画面収録の許可を確認・設定」ボタンから画面収録を許可します。設定を変更してからアプリを再起動する必要がある場合があります。

前面アプリの編集可能な入力欄とそのウィンドウを識別し、対応する単一ウィンドウの入力欄の矩形だけを取得します。デスクトップ全体や他のウィンドウ、入力欄の周囲は撮影しません。所有プロセス、要素の識別情報、位置、選択範囲が変化した場合や、ウィンドウを一意に識別できない場合は取得を見送ります。ウィンドウを動かした場合も次の録音から取得してください。

画像は最大1600×900程度に縮小し、Visionで認識した文字列を上限4096バイトまで保持した後、共通の文脈予算に収めます。画像を保存・IPC出力・クリップボード転送せず、OCR後に解放します。取得本文もフロントエンドへ渡しません。UIには成否と文字数だけを表示します。

OCRは録音の所有スレッドを長時間止めないよう非同期で実行し、文脈利用時には完了を最大約3秒待ちます。遅延・未許可・対象外・失敗時は、利用できるテキストだけ、または文脈なしで認識・補正を続けます。無効化や破棄後は未開始の撮影・OCR段階へ進まず、既に開始したOS処理の画像は完了まで保持される場合があります。OSのメモリをゼロ埋めしたり、スワップを禁止したりする機能ではありません。

## 補正の制約

最終モデルは音声そのものを再解析せず、Whisperの文字起こしと任意の文脈を受け取ります。聞き落とした発話を音響的に取り戻す処理ではありません。周辺テキストは事実や命令の正解ではなく、参考資料です。

Qwen3の非思考モード用のプロンプトとJSON文法制約を用います。文字起こし・文脈内のChatML区切りはJSONエスケープし、役割の区切りにしません。モデルに事実・数値・否定を保つよう指示し、構造不正、空の出力、過剰な増量、句読点・空白・定型的な冒頭の箇条書き指示を除いて原文の6割を超える置換や削除、数値の変更、否定直前の短い文字列の脱落、対比の否定対象の変更、文・節頭の「また」「しかし」の脱落、「いや」に続く明示的な最終訂正の欠落や旧候補を含む列挙・選択肢への変更などを検出した結果は棄却します。

これらは限定的な機械チェックで、意味の同一性やプロンプトインジェクションへの完全な耐性を保証しません。数値を変える必要がある誤認識も、自動では訂正しない保守的な方針です。文字列の限定的な検査であり、日本語の構文解析ではありません。区切りの句読点・空白・括弧を越えて対象を抽出しません。かなが隣接して通常語と区別しにくい接続詞候補や、かなのみの否定対象の厳密照合は見送ります。

「ない」は「うらない」等にも含まれるため、その無条件な回数照合は行わず、判別できる直前断片を検査します。「行ないません」など丁寧語尾の直前にある「ない」も、別の否定としては照合しません。「ではない／じゃない」の明確な否定は、縮約・展開した否定形も許容して回数を保護します。「ません」の回数と従来の否定語の有無の検査は維持します。

かなを含む対比対象では、かな以外の連続した文字列の順序と、先頭・末尾の位置を保ちます。複数の対比では候補を一対一で照合し、1つの候補を別の対比に重複利用しません。例えば「とうきょう駅→東京駅」は許容し、「東京えき→大阪駅」や「とうきょう駅→東京」のような既知の文字の脱落・変更は棄却します。語の読みが同じかを判定する機能ではありません。対比表現の回数と従来の最後の訂正先の検査も維持します。

複数の「いや」がある場合も最後の訂正先の保持を検査しますが、曖昧な旧候補の抽出は見送ります。旧候補の検査は新たな「AやB」「AまたはB」などへの変更に限定し、旧候補のすべての残存を検出するものではありません。「または」、通常の「いやな」、訂正前後で共通する氏名の接頭辞、別の文に残る同名の言及は固定ケースで確認します。数値や否定を変更する言い直しも保守的に棄却し得ます。正しい言い換えでも機械チェックで棄却する場合があり、その場合は原文を確認してください。

入力はJSONを標準入力のパイプで渡し、コマンド引数・環境変数・一時ファイルに文字起こしや文脈を入れません。出力はプレビュー専用です。補正プロセスのネイティブログを保存せず、例外にも入力本文を含めません。実行失敗は固定の段階名、原文保持チェックによる棄却は固定の理由だけで区別します。処理時間・出力・コンテキスト長を制限し、破棄・新しい録音・モデル変更・時間超過では子プロセスを終了します。通常のアプリ終了時も子プロセスを終了・回収してから閉じます。元の認識結果は失敗・キャンセルでも補正結果で上書きしません。

既存の「直接入力」を有効にした場合、それはWhisperの結果を入力する機能です。このPRの補正結果は自動入力しません。

## 比較とCI

同じ公開音声のWhisper small出力と同じ固定文脈で、次の4条件を比較します。全条件で最終補正モデルを動かします。

| 条件 | Whisperへの文脈 | 最終補正への文脈 |
|---|---|---|
| none | なし | なし |
| asr_only | あり | なし |
| correction_only | なし | あり |
| both | あり | あり |

Artifact `correction-evaluation-qwen3-1.7b` / `correction-evaluation-qwen3-4b` / `correction-evaluation-qwen3-8b`に原文・補正結果・CER・棄却数・実行失敗数・時間・RSSを保存します。補正の4条件比較は同じLinux CPU環境で行い、事実と書式を分けた固定28ケース、8Bの同じ旧9ケースの変更前後、差分を評価します。全モデルが揃った比較表は`correction-quality-summary`です。詳細・制約は[補正品質の比較](correction-quality.md)を参照してください。棄却時の原文保持は生成成功と区別し、エンジンの実行失敗ではCIを失敗にします。推論プロセス全体のネットワークを禁止し、GPUを実行していない評価は`NOT TESTED`と記録します。Macのアプリ結合テストとGPUの利用可否検査は継続します。

この比較は、正解語彙を含む固定文脈による感度試験です。実画面のOCR精度や一般的な自然発話の性能を測ったものではありません。実画面OCRの権限・切り出し・音声認識・補正・明示コピー・子プロセスのキャンセルは、別途Macアプリのネイティブ操作CIで検証します。意味・事実・フォーマットに関する機械チェックも指定した制約の範囲に限られ、自由な文章全体の意味評価には人の判断が必要です。VM上の時間・メモリを物理Macの性能として解釈しないでください。

CIの`ci-diagnostics`ビルドは、公開・合成データだけでネイティブ障害を調査する専用実行ファイルです。詳細ログを保存するため、個人の文字起こし・画面情報には使いません。製品を準備する`prepare-native-runtime.py`はこの機能を有効にしません。
