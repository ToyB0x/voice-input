# 画面の使い分け

上部の4タブで作業を切り替えます。起動時は「音声入力」を表示します。

| タブ | 用途 |
|---|---|
| 音声入力 | 録音・停止・破棄、最終結果のコピー。Whisper原文と手動補正は折りたたみから確認 |
| モデル | モデルの取得・検証、音声モデル読込、補正エンジン・CPU／Metal・Qwen再利用の選択 |
| 設定 | 自動補正・直接入力、ショートカット、小型表示、画面情報の取得元／利用先、アプリ更新 |
| 比較・診断 | 処理時間と本文なし診断、Appleの利用可否、固定サンプル診断と録音済み音声の直列比較 |

録音状態・音声モデルの準備状態・エラーは全タブで確認できます。「状態の詳細」では、入力・認識補助・ショートカットなどの現在の状態を確認できます。

タブを切り替えても、入力途中の設定・録音・結果・モデル取得・比較は維持します。切替による設定保存、録音開始／停止、権限要求、モデル取得は行いません。既存の処理中の操作制限はそのままです。

モデル・設定タブの変更は下部の「設定を保存」でまとめて保存します。未保存の変更があれば、音声入力・比較タブへ移動しても保存欄を表示します。通常の音声入力では保存欄を隠して操作領域を広くします。モデルの設定を保存しただけでは読み込み済みの音声モデルは切り替わらないため、「モデルを読み込む」も実行してください。

タブにフォーカスがあるとき、左右キーで前後へ、Home／Endで最初／最後へ移動できます。非選択パネルはキーボード・読み上げの対象から外します。各タブのスクロール位置も切替中は保持します。選択タブやスクロール位置を設定ファイルへ保存しません。

## CIの確認範囲

通常CIの `Browser navigation and layout` では実Chromiumを使い、4画面、クリックとキーボード、未保存設定・比較入力・録音表示の保持、共有保存、意図しないネイティブ操作がないこと、横方向のはみ出しを検証します。通常／狭いウィンドウ・明暗テーマのPNGと `result.json` を `ui-navigation` Artifactに残します。画面データとネイティブ応答は合成サンプルで、実録音・macOSの権限・WebKitの動作を確認したものではありません。

macOSのネイティブ操作テストのロケーターも、実際のタブ／折りたたみを操作する形に更新しています。既知のGHA27 PreviewのWebView空画面問題は引き続き別のPreview GUI workflowで扱い、ブラウザーの成功をmacOS GUIの成功とは扱いません。

発表向けの同音語・画面文脈の実測と補正追加指示は[実験ガイド](context-evidence.md)を参照。
