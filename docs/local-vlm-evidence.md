# ローカル画像理解の評価

Apple Visionの固定分類では、飴まき画像から飴や投げる動作を抽出できなかった。画像から物体・動作を記述する別条件として、Qwen3-VL-8B-Instructをllama.cppのmultimodal CLIで評価する。AFM、Apple Intelligence対応端末、クラウド推論APIを必要としない。

これはまずCIの実験基盤であり、アプリの常駐モデル・通常の画面取得経路へはまだ組み込まない。CPU／Metal双方を扱うCLIを使い、CIではCPUを明示する。Metalの引数を指定しただけで高速化を検証済みとは扱わず、実際の層オフロードを検査する。

- 公式Qwenの固定リビジョン、Q4_K_M言語モデル約5.03GB、F16 projector約1.16GB。ダウンロード容量と実行時メモリは異なる。
- llama.cppは48時間以上経過した固定コミットを使う。モデルはSHA-256／サイズ検証後だけ使用する。
- モデル準備は明示操作。推論はGHAでネットワーク拒否下に置く。
- 公開の組み込み4画像のみ使用。場面名、説明文、文字起こし、正解語を推論へ渡さない。ファイル名も中立名へコピーする。
- 汎用プロンプトから物体・動作・読めた文字・不確かな対象のJSONを得る。2回反復し、原出力と実行情報を保存する。
- 出力トークン512、画像トークン上限4096、文脈8192を固定して記録する。タイムアウト・JSON形式不正を空の観察結果で隠さない。

物体名が含まれるかのチェックは予備的な診断であり、画像理解全体の正解を保証しない。動作の妥当性や幻覚を生の観察結果で確認し、文字補正に渡した後の最終文も別途評価する。単一の合成画像で一般的な性能を主張しない。

実行は `.github/workflows/local-vlm-evidence.yml`。同一コミットのartifactには各画像のハッシュ、モデル・projectorのハッシュ、実行バイナリ・ソース識別子、プロンプト、生成文、所要時間を含める。保存するのは公開テスト画像由来の出力であり、ユーザーの画面や音声を収集する機能ではない。
