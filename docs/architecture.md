# フレームワーク選定

## 要件と比較

macOS 向けの音声入力アプリを Rust で開発する。将来的にはメニューバー常駐、
グローバルショートカット、録音、文字起こし、文章整形、他アプリへの入力を扱う。
音声の認識・解析はローカル処理に限定し、任意で取得する画面コンテキストとの統合も Mac 内で行う。
参考: [Typeless](https://www.typeless.com/ja)。現在はローカル録音から文字起こし・結果表示・コピーまでを実装している。

| 候補 | 特徴 | 今回の判断 |
| --- | --- | --- |
| Tauri 2 | Rust バックエンドと OS の WebView。トレイやショートカットの公式 API / プラグインがある | 採用。小さな設定 UI から始め、OS 連携を Rust 側に追加できる |
| GPUI | Rust で GPU ベースの UI を記述できる | 今回の小さな UI に対して UI・OS 連携の実装判断が増える |
| Iced | Rust で宣言的な UI を記述できる | UI も Rust に統一できるが、常駐アプリの OS 連携を別途組み立てる必要がある |

**Tauri 2 + Rust + vanilla TypeScript / Vite** を採用する。
UI は HTML / CSS / TypeScript、OS 連携・音声処理は Rust が担当する。
Tauri は SwiftUI のようなネイティブウィジェット UI ではない。
現段階では React などの UI フレームワークや不要なプラグインを導入せず、
pnpm / Cargo のロックファイルで依存を管理する。

## ローカル処理と画面コンテキスト

以下は開発コンセプトと後続の実装方針。録音 UI と認識エンジンは接続済み。入力欄の周辺テキストを認識ヒントに使う実験的な設定は実装済みで、入力欄のOCRと軽量モデルによる最終補正プレビューも実装済み。Foundation Modelsの実験的な補正、自動補正と最終結果の直接入力、録音ステータスの小型表示も実装済み。対応実機でのAppleモデル推論品質は確認待ち。

### 音声解析を端末内で完結させる

録音した音声の認識・解析、文脈との統合、認識結果の補正、文章整形はすべて Mac 上で行う。
音声認識エンジンにはローカルで動作するものを選び、クラウド推論や外部 API による解析は使わない。
音声、文字起こし、画面画像、画面テキスト、統合後の解析結果をクラウドへ送信しない。

### 設定フラグによる画面コンテキストの利用

入力精度を高める補助情報として、次の取得方法を個別の設定フラグで有効化できるようにする。
初期状態はどちらも無効とし、利用者の有効化と macOS の権限許可を前提にする。

| 取得方法 | 処理と用途 |
| --- | --- |
| アクセシビリティ | Accessibility API を使い、対象アプリが公開している画面要素のテキストを取得する。入力先の用語・文章を音声認識の補助文脈にする |
| 画面撮影と OCR | 画面画像を取得し、ローカル OCR でテキスト化する。アクセシビリティから取得できない文字情報の補助にも使う |

OCR とその前後処理には、静的な画像・文字列処理や OCR 用のローカル AI モデルを検討する。
OCR やアクセシビリティで得たテキストの意味解析には、必要に応じて Apple の
Foundation Models framework のオンデバイスモデルも選択肢にする。
Foundation Models が画面画像を直接 OCR できることは前提にせず、画像からの文字認識と
取得後のテキスト解析を分けて設計する。

音声情報と取得した画面テキストを端末内で組み合わせ、固有名詞・専門用語の認識や、
入力先の文脈に沿った補正に活用する。各設定が無効な場合は対応する画面情報を取得せず、
音声だけで動作できるようにする。

Accessibility API のテキスト取得にはアクセシビリティ権限、画面撮影には画面収録権限を扱う。
取得範囲・タイミング・一時データの保持期間は実装時に定義する。
Foundation Models の利用可否は対応 OS・デバイス・モデルの準備状況に依存するため、
利用できない環境でもクラウド処理へ切り替えず、利用可能なローカル処理または音声のみで動作させる。

## 現在の実装

- デスクトップウィンドウと日本語の初期画面
- 開発・ローカル `.app` ビルド用コマンド
- Node / Rust のバージョン指定、macOS CI、開発手順
- リモートコンテンツを読み込まない CSP と、録音操作に限定した IPC 権限
- CPAL / Core Audio による既定マイクからの録音、モノラル PCM と入力レベルの計算
- 最大 60 秒のメモリ内バッファ、停止・破棄、録音エラーの表示
- AVFoundation のマイク許可状態・許可要求、拒否後の設定への案内

音声ストリームは専用スレッドで管理し、コールバックは事前確保した上限付きメモリへ書き込む。
音声自体は IPC に含めず、時間・レベル・状態のみを UI に返す。現段階でファイル保存や送信は行わない。
マイク用途の `Info.plist` と hardened runtime 用の音声入力 entitlement を設定する。

文字起こしエンジンには whisper.cpp / whisper-rs と多言語 Whisper base を導入した。
Mac の Metal / CPU、日本語音声、ネットワーク拒否下での推論を CI で検証する。
詳細は [ローカル文字起こし](local-transcription.md) を参照。録音 UI からワーカー経由で実行し、モデルを保持して再利用する。操作と保持期間は [録音から文字起こし](recording-transcription.md) を参照。

## 後続の実装で決めること

1. 常駐・グローバルショートカット・設定保存は実装済み（[利用ガイド](user-guide.md)）。
   今後は必要に応じてログイン時起動・ショートカット選択UIなどを検討する。
2. 既定デバイス以外のマイク選択・物理デバイスの切替。
3. 自然発話によるモデル比較。精度・遅延・メモリ使用量と対応デバイスを検証する。
4. Accessibilityによる入力欄の周辺テキスト取得とローカル認識ヒントは実装済み（[認識補助](recognition-context.md)）。
   入力欄の画面撮影・ローカルOCRとApple Foundation Modelsによる最終補正は実装済み。今後は実機での日本語品質を評価する。
5. 他アプリへの直接入力は任意設定で実装済み（[直接入力](direct-insertion.md)）。
   ローカル文章整形と任意の自動補正・直接入力は実装済み。今後は対応エディターの拡張を検討する。
6. Developer ID による署名・公証は個人利用中は先送り。
   証明書なしの利用手順は利用ガイドに記載し、他者へ配布する段階で対応する。

Tauri 自体が文字起こしや他アプリへの入力を提供するわけではない。
Rust クレートや macOS API 連携で実装し、Mac 実機で検証する。

### ローカル認識補助

独立した初期値falseの`recognitionContext`設定により、録音所有スレッドで入力欄の周辺だけをAXStringForRangeで取得します。ネイティブ側の一時保管庫から一度だけWhisperのinitial_promptへ渡し、キャンセル／無効化で未使用テキストを削除します。取得本文はIPCに含めません。詳細と評価条件は[認識補助](recognition-context.md)を参照してください。

### OCRと最終補正

ScreenCaptureKitで入力欄だけを取得し、Visionでメモリ内OCRします。録音ごとの文脈はネイティブ側の共有リースで管理し、Whisperと補正で独立した利用先フラグを確認します。補正は独立したRust／llama.cpp実行形式へパイプで渡し、プロセス終了で安全にキャンセルできます。補正プレビューは原文を上書きしません。詳細は[ローカルOCR・最終補正](local-correction.md)を参照してください。
