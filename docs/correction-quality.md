# 補正品質と文脈の利用先の比較

`Model evaluation`の補正評価は、同じLinux CPU環境でQwen3 1.7B / 4B / 8Bを比較します。Whisper smallの同一の公開音声と出力を使い、次の4条件で必ず最終補正モデルを実行します。

| 条件 | Whisperへの文脈 | 最終補正への文脈 |
|---|---|---|
| none | なし | なし |
| asr_only | あり | なし |
| correction_only | なし | あり |
| both | あり | あり |

画面情報の利用先フラグを選ぶための感度試験です。正解語彙を含む固定文脈を使用し、実画面OCRや一般の自然発話の精度を測るものではありません。新しい評価に追加OS権限は不要です。Mac上の録音・権限・OCR・補正UI・コピー・キャンセルは既存のネイティブ操作CIで継続します。

## 指標を分ける

- **公開音声のCER**：補正前のWhisper出力と補正後の出力を、同じ正解・正規化で比較します。句読点を正規化するため、CERだけでは書式改善を評価できません。
- **固定テキスト28件の事実チェック**：必須語・禁止語をケースごとに宣言します。数値、否定の対象、固有名詞、訂正後の語、OCRや命令混入を確認します。同義の言い換えでも固定語の検査に失敗する場合があり、汎用的な意味の同一性を保証する検査ではありません。
- **書式チェック**：末尾句点、箇条書きの行数と接頭辞、段落数、フィラー・書式指示・言い直しの語の残存を確認します。意味のある「あの資料」や通常の否定・対比も別ケースで確認します。
- **棄却・実行失敗・無音**：棄却や失敗で保持した原文を「モデルの生成成功」に数えません。CERは利用者へ残る原文を含めた結果、事実・書式の生成成功数は生成された非無音候補だけで示します。別表で原文保持を含む最終テキストの必須語欠落・禁止語残存も集計します。原文保持を生成成功へ加算しません。無音の誤出力や実行失敗はCIを失敗にします。
- **時間・RSS**：モデルの読み込みを含むwall timeと最大RSSです。同じ仕様の別Linux VMでの測定であり、実機Macの速度を表しません。

合成した口述テキストと、既存の公開音声の認識文字列を使う全文保持の回帰ケースを追加しており、新たな自由会話の音声コーパスを収集したわけではありません。評価結果だけでモデルを自動選択したり、補正を自動採用したりしません。

## 変更前後の確認

8Bの[固定ベースライン](../evaluation/correction-baseline/README.md)は前PRで実測した9件です。モデルの固定情報と入力・文脈・正解が一致するケースだけを、現在の同じ検査で再採点します。追加19件は変更前後の集計に混ぜません。変更前には「会議は水曜日いや木曜日です。」という言い直しが残っていました。

補正プロンプトでは発話を周辺資料より優先し、明確な自己訂正と段落指定を固定のJSON入出力例で示します。例は評価ケースのコピーではありません。利用者のtranscript/contextは引き続きJSONエスケープし、ChatMLの役割を追加させません。数値・否定・大幅改変などの既存の棄却処理と、原文保持・明示コピーを維持します。正しく整形できるか、他のケースに悪化がないかは実モデルの結果で確認します。

4BにはPR #14で実測した固定20件と、Whisper small / medium / large-v3-turboの各4条件を追加しました。旧20件は現在と同じ制約で再採点し、新規8件を比較に混ぜません。音声経由の比較は認識文字列・文脈・正解がすべて一致した入力だけを組にし、異なる入力の除外数を明記します。異なるランナー間の速度比較には使いません。

`evaluation/correction-guard-cases.json`には、問題のある候補11件と正常な整形20件、保守的方針で棄却する正常な否定の言い直し1件の固定ペアを保存しています。旧実装では問題のある候補9件が通り、新実装では問題候補11件すべてを棄却し、正常な整形20件はすべて通ります。否定の言い直し1件の棄却は意味の破壊を防いだ成功に数えず、方針上の制限として別に表示します。`guard-regression.json`で誤受理と誤棄却を別々に確認できます。この固定集合での結果は、実利用の誤り率や一般的な意味保持の保証ではありません。

接続詞「また」「しかし」、否定直前の短い文字列、対比の否定対象、明示的な言い直しの旧候補の残存を限定的に検査します。正しい言い換えも棄却し得るため、生成品質の改善と棄却による原文保持を分けて読みます。

## 再現性とArtifact

音声、モデル、コーパス、補助ケース、エンジンのCargo.lock、ランタイムソース、実行形式、ソースコミットの識別情報を記録します。ASRの`comparison.json`は`context-evaluation-v2`で、各出力のSHA-256とネットワーク禁止の確認を持ちます。古いコミット・別コーパス・書き換えたASR出力は補正評価の前に拒否します。

補正の`report.json`は`correction-quality-v2`です。ケースごとに途中結果を原子的に保存し、`complete`がfalseのレポートでは比較を発表しません。全3モデル・全4条件・全補助ケースが揃い、同一入力・ソース・採点条件・通信禁止を確認できたときだけ比較表を作ります。総数・スコア・制約ラベルも観測結果から再計算して検査します。

Artifacts:

- `correction-evaluation-qwen3-*`：`report.json`、`summary.md`、原文から補正候補への`cases.diff`。4Bと8Bは固定ベースラインとの`baseline.diff`も保存します。4Bは音声経由の`route-baseline.diff`と固定判定の`guards/guard-regression.json`も保存します。棄却・失敗による原文保持を各差分へ明記します。
- `correction-quality-summary`：モデル別・利用先別のCER、事実／書式・棄却数の比較、8Bの同一9ケース、4Bの同一20ケースと一致した音声入力での変更前後、JSONと差分です。

評価はモデルを明示準備した後、Linuxのseccompでネットワークを禁止して実行します。CPUのみの評価はMetalを`NOT TESTED`と記録します。Apple Foundation Modelsの実機評価・モデル選択プリセット・モデル常駐による高速化は後続作業です。証明書・公証は個人利用中は引き続き先送りします。
