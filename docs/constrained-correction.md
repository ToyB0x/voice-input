# 制約付き補正とCPU品質評価

全文の書き直しでは、宛先や動作が脱落することがある。Qwenの新しい `replacements` モードは、ローカルの読み辞書に登録された語について、原文内の出現箇所と参考文脈に実在する置換先から候補を作る。モデルは候補IDだけを選択し、アプリ側が選択箇所だけを書き換える。候補以外の本文、数値、語尾、動作はそのまま残る。重複・重なり・未知ID・不正な辞書を棄却し、既存の意味保持ガードも適用する。

この段階ではヘルパーと評価用の明示モードであり、既存アプリの全文整形を自動で切り替えない。構造化出力は意味の正しさを保証しない。辞書の「同じ読み」は呼び出し側が用意する情報であり、モデルの自己申告で検証したことにはしない。辞書には複数語に一致する曖昧な表記を登録できない。単語境界の形態素解析は未導入で、部分文字列候補の意味判断はモデルに依存する。

```json
{"mode":"replacements","transcript":"はしを渡ります。","context":"川に架かる橋です。","dictionary":[{"reading":"はし","forms":["橋","箸","はし"]}]}
```

`local-correction /absolute/model.gguf cpu --compare` にJSONを標準入力で渡す。選択結果、候補、採否、処理時間を比較モードで返す。通常モードは従来どおり採用した本文だけを返し、個人の本文をログへ出さない。

## 評価

`.github/workflows/correction-quality.yml` はQwen3-4B/8Bの固定GGUF、同じ本番ヘルパー、CPU推論を用いる。モデル取得後はネットワークを拒否する。実行順を反転して2回測定し、入力・モデル・バイナリ・ソース・評価データの識別子と各候補をartifactに保存する。保存対象は公開の合成テストのみ。CPUの選択モードは最大30分の総処理予算、15分の生成予算を持つ。モデルサイズや遅いCPUによる失敗を短い対話用タイムアウトと混同しない。親プロセスも実行全体を制限する。

雨／飴の実機失敗を再現した文章に加え、別の同音語、人名、宛先、数値、否定、対比、長文、意図的反復、無関係な文脈、命令混入を含む。かな入力は辞書対象語だけを復元し、全文の漢字変換ではない。OCR生文字列と改行を取り除いた対照は同じ文脈文を使う。

品質ゲートは小さな開発セットでの全文一致と反復の安定性。棄却やタイムアウト後の原文復帰はモデルの成功に数えない。全文書き換えの旧方式も少数の同一ケースで比較するが、その失敗を新方式の成功として数えない。未使用の評価セット、実際の複数話者音声、実機Metalでの検証は別途必要で、この合成テストの成功率を一般精度として表示しない。

同じ「あめが降っています」に誤った画像説明だけを渡すケースは、補正器だけでは判別できない。`adversarial-context` は必ず報告するが採用ゲートとは別に扱う。正しい文脈による改善と誤った文脈による改悪の両方を確認し、取得元・時刻・対象アプリの照合を後段で加える。

## 全文補正の追加防御

AFM/Qwen共通の検証に、漢字・カタカナ・ASCIIの名前＋「さん／様／氏／先生」の脱落検出を追加した。「田中さんへ資料を送ります」から「資料を送ります」への変化を棄却する。自己訂正の旧候補は保持対象から除く。これは限定的な文字列検査で、かなだけの名前、敬称のない名前、複雑な自己訂正を網羅する固有表現認識ではない。制約付き補正による編集範囲の制限と併用する。
