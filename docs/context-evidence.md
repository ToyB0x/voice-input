# 発表用：日本語の同音語と画面文脈を実測する

「あめがすごいですね」の同じ合成音声を、台風とキャンディの2シーンで比較する小規模な実験。実測値からHTML・PDFスライドとJSONを生成する。精度改善がなかった条件や取得失敗も残す。日本語と他言語、他製品の精度比較はしない。

## 通常アプリの追加指示

「モデル」→「補正の追加指示」に、例えば次を入力して設定を保存する。

> 文脈から判断できる同音語は自然な漢字表記にしてください。判断できない場合は推測せず元の表記を保ってください。

任意・初期値空欄。AppleとQwenの手動プレビュー・自動補正・録音済み音声の比較へ同じ保存値を渡す。固定サンプル診断は標準条件を維持する。指示はこのMacの設定ファイルへ保存し、本文なし診断や比較レポートには含めない。UTF-8で1536バイトまで。意味・数字・否定などの既存ガードは無効化しない。補正が改善する保証はない。

## CI実験

Actionsの「CI」をRun workflowで実行し、`context_evidence`を有効にする。またはmainに入った後に「Japanese context evidence」を手動実行する。通常のPR・pushではモデル取得・実推論を追加しない。

1. macOS 27で既存のWhisper base・Qwen3-1.7B-Q8_0ヘルパーをビルド。モデルは既存カタログの固定revision／SHA-256で検証する。
2. インストール済みの日本語`say`音声から1本のWAVを生成。全条件で同一ハッシュの音声を使用。音声未導入なら失敗とし、英語へ代替しない。
3. 専用のAppKitウィンドウに文脈テキストまたは文字なし画像を表示し、ビューをPNGへ描画する。別アプリや画面全体の撮影はしない。
4. 専用ウィンドウの自プロセスに対してAX consumer APIの範囲取得を試す。OS権限などで失敗した場合は取得不可とする。直接与えた対照テキストをAX取得と呼ばない。
5. 同じウィンドウの描画結果にApple Vision OCR／画像分類を実行。OCRは標準実行が失敗した場合のみCPU指定でも試し、各試行を記録する。分類の実ラベルと信頼度をそのまま使い、正解の「雨／飴」へ手動変換しない。
6. 文脈なし／直接テキスト／AX／文字画像OCR／文字なし画像OCR／画像分類／逆のテキストを比較。Whisperヒント・補正・両方の利用先、追加指示の有無も比較する。
7. 条件を直列に2反復し、2回目はシーン・条件の順を反転。Qwenは重みだけ再利用し、リクエストごとに新しい文脈・KVを作る。`--serve-compare`は候補とガード結果を観測する実験用モード。
8. 推論プロセスのネットワークは禁止。Apple Foundation Modelsが利用不可なら未実行とし、Qwenへの暗黙置換や模擬生成はしない。

基準語・期待語は評価側だけに置く。モデルにはASRの実出力、選択した文脈、追加指示だけを渡す。同一のWhisper入力は条件間で共有し、各行に同じ認識時間を記録する。表の行の時間を足して実行時間と解釈しない。

## Artifact

- `japanese-context-measurements`: 合成音声・描画画像・AX/OCR/Visionの生データ、候補・採否・原文保持・時間・ソースrevision・モデル／バイナリ／音声／画像のハッシュを含むJSON。
- `japanese-context-presentation`: 実測から生成した自己完結の`slides.html`、16:9の`slides.pdf`、`summary.md`、`results.json`。HTMLはブラウザで開くだけ。値のないテンプレートを実測スライドとして公開しない。

Artifactは30日で失効するため、発表に使うファイルはダウンロードして保存する。採用する実測レポートは`evaluation/context-evidence/baseline/`にも固定し、ソースとCI URLを記録する。

## 解釈の限界

- 雨／飴のアクセントは方言・イントネーションによって手掛かりになる。同じ合成音声を二つの意図へ流用するため、音響上の正解を二つ用意した実験ではない。
- 評価は期待語／逆の語／両方／判断不能の出現判定。数字・名前・全文の意味保持を保証しない。
- 反復は同一データの再実行。独立した発話数や一般的な正解率として発表しない。
- ウィンドウ描画のOCRと、実機での画面撮影・権限・通常アプリの入力欄限定クロップは別の検証。
- 現在の通常アプリはAXの入力欄周辺とOCRの取得テキストだけを利用する。画像分類はこの実験系だけ。画像をWhisper／Qwen／Apple Foundation Modelsへ直接渡す機能やローカルVLMは追加していない。
- 「OCRにはテキストを読む役割がある」「文字なし画像の意味には別の視覚処理が必要」は構造の説明であり、Vision分類のラベルが今回の画像や認識精度に役立つかは実測で確認する。

スライドとブラウザCIの日本語フォントはGoogle FontsのNoto Sans JP（2026-03-25の固定commit、SHA-256検証、SIL OFL 1.1）を使用する。ライセンスは`evaluation/context-evidence/assets/NotoSansJP-OFL.txt`。

## 固定した実測結果（初回パイロット）

[測定ジョブ](https://github.com/ToyB0x/voice-input/actions/runs/40344979563/job/121649529040)で156行を記録した。独立した発話は1本であり、156発話の試験ではない。2反復を行った。

- 文脈なしのWhisperは「あめ」ではなく「目がすごいですね」を出力。天気テキストをヒントにすると「雨がすごいですね。」へ変わった。
- キャンディの直接テキストをヒントにすると「メガスゴイですね。」となり、期待した「飴」にはならなかった。
- 画像分類はキャンディを`candy / lollipop`（約0.983）、台風画像を`ocean / sky / cloudy`などと認識した。今回の分類ラベルでは最終変換の改善は確認できなかった。
- 逆の天気文脈をキャンディ条件へ与えると「雨」へ誘導された。参考文脈が誤っている場合の影響がある。
- AXは`cannotComplete`、Vision OCRは標準／CPU指定とも`TextRecognition.CRImageReaderError` code 9。取得成功として数えない。Apple FMはGHAで`deviceNotEligible`のため推論未実施。
- Qwenの補助テストでは、標準指示で「本番には」「田中さんへ」が脱落した候補をガードが採用した。否定・数値の検査だけでは意味保持を保証できない。追加指示ありではこの2例を維持したが、一般化しない。

`baseline/results.json`と音声・画像・取得診断を固定した。`Context evidence presentation` CIはこれを検証してスライドを再生成し、本文や表のはみ出しも検査する。実測元ソースと資料生成コードの版は別々に追跡する。
