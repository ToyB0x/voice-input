# LT用：「この『あめ』、どっち？」

既存の回帰試験や比較画面とは別の、約3〜4分の小さな実験。一般補正の品質ゲートを緩める変更ではない。

1. **音声だけ**：同じ合成音声「あめがすごいですね」をWhisper large-v3で2回認識。ヒントは空。出力に正解・不正解は付けない。
2. **短い文章＋音声**：「今日は台風だ」「今日はハロウィン。特別なキャンディがたくさん用意されているらしい」を個別に追加。画像は渡さない。
3. **文字なし画像＋音声**：雨の街／屋根からの飴まき。人の説明文・OCR・シーンID・期待語はモデルへ渡さない。

音声認識結果は全条件で共有する。後段のQwen3-VL-8B-Instructは、音声のバイト列ではなくASRの「あめ」の部分だけをひらがなに戻した文と追加の手がかりを受け取り、あらかじめ与えた「雨／飴／不明」から選択する。「あめ」以外の本文はコードで保持する。画像を使う段階でもモデルは同じ。画像では、見えている物や動きをモデル自身が短く記述してから表記を選び、その観察文も記録する。人が画像の説明文を追加する処理ではない。画像内文字を読むOCR処理や、手動の画像ラベル対応は使わない。

文章ヒントは[evaluation/ame-lt/scenarios.json](../evaluation/ame-lt/scenarios.json)で調整できる。想定する正解は採点とスライド構成だけに使い、モデル入力へは混ぜない。文章は意図的に分かりやすい手がかりとする。音声のアクセントを聞き分ける試験、一般的な音声入力精度の比較ではない。

## 実行と発表

GitHub Actionsの **Ame LT three-stage demo** を手動実行する。固定モデルを準備した後、ASRと文脈判断はネットワーク禁止で実行する。各条件2回の候補・実入力・時間・音声／画像／モデルのハッシュをresults.jsonへ保存する。

成果物 ame-lt-presentation:
- presentation/slides.html：音声を再生できる6枚のスライド。左右キーで移動。
- presentation/slides.pdf：配布用PDF。
- presentation/slide-*.png：全ページの画像。
- presentation/speaker-notes.md：短い発表メモ。
- evidence/results.json：実測値と全入力・出力。

スライドは完了した実推論からのみ生成する。結果が期待と違っても実出力を掲載し、品質ゲートは失敗にする。失敗時に成功文へ差し替えない。合成音声・合成画像は既存の公開実験素材を再利用する。

## Macアプリの「デモ」タブ

「デモ」→「デモ用モデルをまとめて準備」を選びます。Whisper large-v3、Qwen3-VL 8B Q4_K_M、画像エンコーダー（合計約9.3 GB）を固定版・SHA-256検証付きで取得します。16 GB以上のメモリを推奨します。音声だけなら「音声モデルだけ準備」も利用できます。通常のモデル設定欄への反映や設定保存は不要です。

1. **① 音声だけで実行**：同梱音声をヒントなしで認識します。音声プレイヤーで同じ素材を聴けます。再実行すると以前のデモ結果をリセットします。
2. **② 文章付きで実行**：台風／ハロウィンの2文で比較します。文章は各256文字まで調整できます。画像を渡しません。
3. **③ 画像付きで実行**：雨の街／屋根からの飴まきの2画像で比較します。②の文章、画像説明、OCRは渡しません。

②③から開始した場合は①を自動で一度実行し、以後はそのASR結果を共有します。各ボタンはCPU・温度0・seed 0・固定モデル・対象語だけの置換を自動で選びます。文章／画像は1回が発表向け、2回は逆順の再実行確認です。ASRの2回独立実行を含むGHAの完全な10行試験とは、この反復範囲が異なります。Metalでの結果差を混ぜないため、現時点のデモはCPU固定です。

モデルの候補と実測時間、画像の場合はモデルの観察文を表示し、不明なら元の表記を保ちます。実行エラーや想定外の発話を成功文に置き換えません。中止・結果の消去・実行結果JSONの保存ができます。JSONには調整した文章とモデル入力・出力が含まれます。

通常の録音・補正・モデル準備・更新との競合は既存の排他制御で防止します。デモは通常設定を保存せず、自動入力もしません。実行時に通常音声モデルを解放するため、通常入力へ戻る場合はモデルを再読み込みしてください。デモは比較機能と共通のワーカーを使用します。

推論にクラウドAPIは使いません。アプリ実行にはGHAと同じネットワーク禁止サンドボックスは掛けていません（レポートの `networkDenied: false`）。固定の同梱素材を用い、他アプリの画面やマイクを取得しません。

開発ビルドでは `pnpm run prepare-native` が固定コミットのllama.cppを取得し、CPU用の `llama-completion` と `llama-mtmd-cli` を静的リンクで構築・署名します。モデル重みはビルド時には取得しません。macOS CIは同梱バイナリのOS要件と外部ライブラリへの依存を検査します。
