# 個人利用ガイド（Developer ID・公証なし）

当面は自分のMacで使うため、Developer ID証明書・Appleの公証・配布用インストーラーは用意しない。
以下は自分でソースを確認してローカルビルドする手順。音声の推論はMac内だけで行う。
モデルの明示的な準備と開発依存の導入にはインターネットを使う。

## 自分のMacでビルド・配置する

macOS 27以降、Xcode 27以降またはmacOS 27 SDKを含むCommand Line Toolsとmiseが必要。Node.js・pnpm・Python・CMake・Rustは[開発ツールのセットアップ](toolchain.md)で導入する。
[開発環境の説明](../README.md#macos-で開発する) に従って導入する。

```sh
git clone https://github.com/ToyB0x/voice-input.git
cd voice-input
mise trust
mise install
mise exec -- pnpm install --frozen-lockfile
# Developer IDではなくアドホック署名でローカル.appを作る。
APPLE_SIGNING_IDENTITY="-" mise exec -- pnpm run tauri build --bundles app --ci -- --locked
mkdir -p "$HOME/Applications"
ditto "src-tauri/target/release/bundle/macos/Voice Input.app" \
  "$HOME/Applications/Voice Input.app"
open "$HOME/Applications/Voice Input.app"
```

「未署名」はDeveloper IDによる署名・公証がない意味。アドホック署名は開発元の身元を証明しない。
この手順は.appだけを作り、証明書・Appleアカウント・公証の資格情報は不要。
Intel MacはそのMacでのビルドが必要で、現在のCIによる動作確認対象はApple Siliconである。

自分でビルドしたアプリは通常そのまま起動できる。ダウンロードや転送による隔離属性などで
Gatekeeperが起動を止めた場合は、入手元と内容を確認し、一度起動を試してから
「システム設定 → プライバシーとセキュリティ」で対象アプリの「このまま開く」を選ぶ。
表示・手順はmacOSのバージョンにより異なる。
[Appleの案内](https://support.apple.com/ja-jp/102445) も参照する。
「破損」「マルウェア」などの警告を無条件に解除せず、まず入手元や再ビルドを確認する。
システム全体のGatekeeperを無効にする必要はない。

## CIで検証したアプリを使う

ビルドが完了したActionsのArtifact `voice-input-macos-ARM64-<試行番号>`には、Apple Silicon向けの`Voice-Input-macos.zip`と`provenance.json`を保存する。後続の画面テストが失敗していても保存するため、まずCI結果と画面Artifactを確認する。JSONのソースリビジョンとSHA-256を確認し、ZIPを展開して`Voice Input.app`を自分のApplicationsへ配置する。モデルや個人設定は含まない。Developer ID署名・公証はないため、隔離属性で起動できない場合は上記の対象アプリを「このまま開く」手順を使う。

## 画面を切り替える

起動時は「音声入力」を表示する。初回の準備は「モデル」、自動補正・直接入力・権限・更新は「設定」、性能や方式の確認は「比較・診断」を使う。設定を変えたら下部の「設定を保存」でまとめて保存する。タブ移動では保存・取り消しを行わない。[画面の使い分け](navigation.md)を参照。

## モデルを準備して設定する

```sh
# リポジトリのルートで実行。精度を優先する暫定候補small（約488 MB）。
python3 scripts/prepare-transcription-model.py --model small models/ggml-small.bin
# アプリへ入力する絶対パスを表示する。
python3 -c 'from pathlib import Path; print(Path("models/ggml-small.bin").resolve())'
```

速度・メモリ優先なら `--model base models/ggml-base.bin`（約148 MB）を使える。
[比較結果と制約](model-evaluation.md) を参照する。
モデルは別ファイルなので、アプリ更新後も同じ場所に保持する。

アプリでモデルの絶対パスとMetal / CPUを選び、「モデルを読み込む」。
「設定を保存」でモデルのパス・実行方式・録音ショートカットを保存する。
保存したモデルは次回起動時に自動で読み込む。起動時にマイクの許可は求めない。
設定の保存だけで現在読み込み済みのモデルは切り替わらない。
今すぐ変える場合は「モデルを読み込む」を使う。
モデルの移動・削除・破損やGPUエラーは画面で案内し、外部サービスへ切り替えない。

## 別アプリで作業しながら録音する

初期ショートカットは **Command + Shift + Space**。押して離すと録音開始、もう1回押して離すと停止し、
モデルが準備済みならローカル文字起こしする。最大60秒で自動停止する。
初回の録音時だけOSのマイク許可を確認する。拒否済みなら画面からシステム設定を開ける。
「録音入力」には、その録音で実際に選んだデバイス名・サンプルレート・チャンネル数を表示する。外付けマイクを使う場合は、先にmacOSの「システム設定 → サウンド → 入力」で選び、録音を開始する。変更した場合は一度停止して録音し直す。
入力レベルは同じ録音データのRMSをdBFSで表示する。バーの範囲は-60〜0 dBFS、数値はそれより小さい音も表示する。高速表示が利用できない場合も通常の状態取得で表示を続け、失敗理由を画面に示す。
録音中・認識中はメニューバーの `VI 録音中` / `VI 処理中` で確認できる。
認識中やモデル読み込み中は次の録音を始められない。

ウィンドウの赤い閉じるボタンは非表示にする操作。録音・認識や常駐は継続する。
メニューバーのVIから「設定・認識結果を表示」で画面へ戻り、結果を確認して「結果をコピー」する。
Dockアイコンからも画面を再表示できる。
バックグラウンド操作の成功時に前面アプリを切り替えたり、結果を自動コピーしたりはしない。
他アプリへの直接入力は初期状態では無効。使う場合は設定で有効にして保存し、
アクセシビリティ権限を許可する。[直接入力の操作・対応範囲](direct-insertion.md) を参照。
無効時や入力が見送られた場合は、明示的にコピーして入力先へ貼り付ける。
初回の権限要求やエラー時には確認のため画面を表示する。
終了はVIメニューの「Voice Inputを終了」、またはアプリの終了操作（Command + Q）を使う。
ログイン時の自動起動は追加していないため、再ログイン後は自分で起動する。

ショートカットは `Control+Alt+KeyV` などに変更して「設定を保存」すると直ちに反映する。
`Command`、`Control`、`Alt`（Option）のいずれかを含める。空欄で保存すると無効になる。
他アプリやmacOSが使う組み合わせは避ける。登録失敗時はエラーを確認して別の組み合わせを選ぶ。
OS側の予約などで登録できても期待どおり届かない場合は、実際に別アプリを前面にして確認し、変更する。
製品のショートカットにはCarbonのホットキーAPIを使い、ショートカット自体にアクセシビリティ・入力監視・画面収録の許可は不要。
任意の直接入力または入力欄による認識補助を使う場合にアクセシビリティ権限が必要になる。

Qwenの読込待ちを減らす場合は[モデル再利用・処理時間](correction-reuse.md)を参照。初期状態は無効で、Appleモデルには適用しない。

## 設定・一時データ・更新

保存先は `~/Library/Application Support/dev.toyb0x.voiceinput/settings.json`。
保存項目はバージョン、モデルのパス・実行方式、ショートカット、直接入力・自動補正・小型表示・Qwen再利用、取得元・利用先の有効／無効、補正エンジンの設定だけ。処理時間や本文は保存しない。
設定ファイルは所有者だけが読み書きできる権限で置換保存する。
音声・認識結果・画面情報・モデル本体はこのファイルに保存しない。
音声と結果の保持・破棄、コピー後のクリップボードについては
[録音と文字起こしの説明](recording-transcription.md#音声と結果の扱い) を参照する。

設定ファイルが不正な場合は初期値で起動し、エラーを表示する。
元のファイルは自動で上書きしない。必要なら終了してファイルを退避・削除し、設定し直す。
明示的に「設定を保存」した場合は新しい設定に置き換える。

更新時はアプリを明示的に終了し、ソースを更新して再ビルドする。
Finderで新しい.appを `~/Applications` の既存.appと置き換える（設定ディレクトリは残す）。
アドホック署名ではビルド変更などによりmacOSがマイク許可を再確認する場合がある。
直接入力のアクセシビリティ許可も、更新で再確認が必要になる場合がある。
許可スイッチがオンなのにアプリで「未許可」と表示される場合は、アプリを終了し、
アクセシビリティ設定の古いVoice Input項目を「−」で削除して、
「＋」から現在配置している.appを追加し直して許可する。その後アプリを再起動する。
必要に応じて終了後に `tccutil reset Accessibility dev.toyb0x.voiceinput` でこのアプリだけの許可をリセットし、
起動して許可し直すこともできる。アプリ自身が自動で許可をリセットすることはない。
許可したのに録音できない場合は「システム設定 → プライバシーとセキュリティ → マイク」で
配置したVoice Inputの許可を確認する。設定・モデルを残したまま.appを更新できる。
削除する場合は終了後に.appと必要に応じて上の設定ディレクトリ・自分で配置したモデルを削除する。

## 自動検証の範囲

週次・手動の[完全Mac CI](ci.md)は証明書・公証なしの.appを通常起動し、実際のマイク許可・拒否、録音・認識・コピー・破棄を検証する。
TextEditを前面にしてウィンドウを閉じた状態のショートカット、トレイ状態とメニュー操作、
終了・再起動後の設定復元、空の結果、ショートカットの無効化も検証する。
CIドライバーの画面操作・撮影の権限は製品側の権限とは別で、使い捨てランナー内で利用する。
画像・判定はActionsの `macos-window-smoke-1` Artifact（末尾は試行回数）の `desktop/` に保存する。

個人MacのGatekeeper表示や既存の権限設定、物理マイクの音質、実機GPUの速度はそのMac固有であり、
CIから個人Macの許可を操作することはできない。必要な初回操作は上の利用手順にまとめている。
証明書・公証は将来配布する段階で検討する。

## 入力欄による認識補助（実験的）

設定で有効にすると、録音開始時の別アプリの入力欄からカーソル周辺だけを取得し、ローカルWhisperの認識ヒントに使います。初期状態は無効で、直接入力とは独立しています。取得できない場合は通常の音声認識を継続します。テキストの保存・ログ出力・クラウド送信はしません。権限、取得範囲、再試行や認識精度の制約は[認識補助ガイド](recognition-context.md)を参照してください。

## OCRと最終補正

取得元（Accessibility／入力欄のOCR）と利用先（Whisper／ローカル最終補正）を個別に選べます。最終補正は元の認識結果を保持するプレビューで、自動入力せず明示的にコピーします。補正モデルの準備と画面収録の許可、キャンセル、比較の制約は[ローカルOCR・最終補正](local-correction.md)を参照してください。

## モデルの準備

アプリ内から公式モデルを準備する操作・プリセット・保存先は[モデル準備ガイド](model-setup.md)を参照してください。取得は明示操作時だけ行い、音声や画面情報は送信しません。既存の手入力パスも利用できます。

Apple Intelligence対応Macで最終補正にAppleのオンデバイスモデルを試す場合は、[Apple Foundation Modelsの利用・診断手順](apple-foundation-models.md)を参照してください。音声認識は引き続きWhisperで行います。新しいTCC権限の自動付与や署名・公証は行いません。

## 対応OSとCIの結果

対応OSはmacOS 27以降です。macOS 26以下はサポート対象外です。アプリのビルド・表示・権限の検証とRelease生成には、GitHub ActionsのPreviewイメージ `xcode-27` を使用します。26上の音声エンジン単体テストは補助検証です。

アプリArtifactはビルド完了時に保存するため、その後の画面・権限テストが失敗した場合もダウンロードできます。`provenance.json`のリビジョン・SHA-256を照合し、対応するCI結果と`macos-window-smoke` Artifactも確認してください。Artifactの存在は動作確認の成功を意味しません。

実機では、起動と画面表示、マイク・アクセシビリティ・画面収録の許可と拒否、録音から文字起こし・コピー、任意の直接入力とOCRを確認します。Appleモデルは診断で実際の利用可否を確認し、利用できる場合に短い発話の補正と原文保持を試してください。GHAの`deviceNotEligible`は実機での利用不可を意味せず、CIでは推論未検証として扱います。
